# Auditoria de Acessibilidade · WCAG AA

**Data:** 2026-07-23
**Ferramenta:** axe-core 4.10.2 via Playwright (Chromium headless)
**Cenário:** rotas públicas críticas do Cathedra em duas viewports
**Regra principal auditada:** `color-contrast` (WCAG 2.1 AA · SC 1.4.3)
**Rotas testadas:** `/`, `/atrium`, `/pricing`, `/jornadas`, `/glossario`, `/oracao/rosario`, `/lectio`, `/about`
**Viewports:** desktop `1280×900`, mobile `390×844`

## 2. Causa raiz (por padrão, não por instância)

Três padrões concentraram >90% das violações:

1. **Dourado de marca (`#c9a84c`) usado como cor de texto sobre fundo claro.**
   Ratio exato = 4.5:1 (fica no limite AA para texto normal e falha para
   axe por precisão de ponto flutuante). Presente em `Footer`, `Sidebar`,
   `BottomNav`, `AppHeader`, `Catechism` e `JornadaCompletePage`.

2. **Números decorativos ("01", "02"…) com opacidade `/25`** sobre `bg-background` em
   `AtriumHome`, `AtriumJornadasPage`, `AtriumBuscarPage`, `AtriumBibleReader`,
   `AtriumCatechismReader`. Ratio ~2:1 — reprovado mesmo para elementos "grandes".

3. **Opacidades acumuladas** em elementos utilitários (`text-primary/60`,
   `text-secondary/70/80`, `text-stitch-*-variant/70`) usados como texto
   real, não como decoração — resultando em cinzas médios (`#808080` etc.).

---

## 3. Estratégia de correção

Tokens semânticos foram adicionados a `src/index.css` para segregar decoração
de tipografia acessível:

```css
--gold: #c9a84c;             /* backgrounds, borders, ícones em fundo escuro */
--gold-text: #8a7020;        /* texto sobre fundo claro (~6.8:1 vs #fff) */
--gold-text-strong: #6d5a1a; /* hover/link ativo em fundo claro */
```

**Regra editorial (nova):**
- `bg-*`, `border-*`, `ring-*` e ícones podem seguir usando `#c9a84c` (via
  `--gold`) e mantêm o dourado pleno da marca.
- **Nunca** usar `color: #c9a84c` em texto sobre fundo claro. Usar
  `text-[color:var(--gold-text)]` (Tailwind arbitrário) ou `GOLD_TEXT`
  (constante nos componentes com estilo inline).
- Opacidade `/50`–`/70` só para elementos verdadeiramente decorativos e
  aria-hidden. Para texto real: mínimo `/85` em superfície clara.

## 5. Dívida técnica declarada

Ainda pendentes:

- **`/` (landing)**: `btn-premium-ghost` com `#b3b3b3` sobre branco (ratio 2.1)
  em um botão de header. Corrigir na próxima onda do design system dos botões.
- **`/pricing` mobile**: `text-muted-foreground/40-50` em rodapés de card de
  plano — aumentar opacidade para `/70`.
- **`/about`**: âncoras internas `text-muted-foreground/60` — subir para `/85`
  ou trocar para `text-foreground`.

Nenhuma dessas envolve o dourado de marca; são cinzas locais de componente.

## 6. Gate no CI

Workflow: `.github/workflows/a11y-axe.yml`
Script: `scripts/a11y-axe-report.py`

- Roda em cada PR e em push para `main`.
- Auditor axe com `color-contrast` + `button-name` + `link-name` +
  `image-alt` + `label` + `aria-required-attr` + `duplicate-id-aria` +
  `html-has-lang` + `landmark-one-main`.
- Rotas testadas: `/`, `/atrium`, `/jornadas` (as três mais visitadas).
- Falha o build se houver **qualquer violação `serious` ou `critical`**.
- Publica `reports/a11y/` como artefato (retention 14 dias): `violations.json`
  + `summary.txt`.

## 7. Como reproduzir localmente

```bash
# 1) Dev server já rodando em http://localhost:8080
BASE_URL=http://localhost:8080 python3 scripts/a11y-axe-report.py

# 2) Ver resultado
cat reports/a11y/summary.txt
jq '[.[] | select(.route=="/lectio")]' reports/a11y/violations.json
```

Requisitos: Python 3.11+, `pip install playwright`, `playwright install chromium`.
